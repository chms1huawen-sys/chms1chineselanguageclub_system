## 需要备份的内容

- 数据库角色、结构、业务数据及 Auth 账号数据。
- Storage 内的实际照片和附件。数据库的 Storage 元数据不包含文件内容。
- 本仓库中的 Edge Functions、迁移文件和部署配置。
- 单独保管平台配置与密钥恢复说明，不能把密钥放进 Git 或聊天。Vault 加密资料的恢复需要另行核对密钥及官方恢复步骤。

依据：[Supabase 官方备份恢复说明](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore)及[文件下载说明](https://supabase.com/docs/guides/storage/management/download-objects)。不能把下面的数据库命令当成完整网站备份。

## 导出准备

1. 先确定只供授权管理员访问的备份位置，建议电脑本地加密磁盘，再保留一份独立介质副本。不要放在公开仓库、网站目录或未经确认的同步网盘。
2. 安装并启动官方 Docker Desktop，确认 Supabase CLI 已登录正确组织且链接正确项目。不要重置数据库密码来绕过缺少连接信息。
3. 使用已有安全配置连接；连接密码由用户在本机输入，不能写在文档、脚本或命令历史里。
4. 每次创建新的时间戳目录，不覆盖旧备份，不自动清理。

已链接正确项目后，数据库导出命令为（每一行单独运行）：

```powershell
npx supabase db dump --linked --role-only -f backups/本次日期/roles.sql
npx supabase db dump --linked -f backups/本次日期/schema.sql
npx supabase db dump --linked --data-only --use-copy -f backups/本次日期/data.sql
```

需要先创建目录。每次检查退出码、非空文件与 SHA-256 哈希；任何失败都不能标记备份完成。本项目对 auth/storage 的自定义权限和触发器必须与仓库迁移文件一并保留，CLI 默认结构导出不代表已经覆盖所有托管结构。Cron、Vault、平台 Auth 配置和实时订阅设置需单独记录恢复步骤。

Storage 文件需要另行下载，包含私有附件，不能只导出 public 文章照片。首次全量导出也会产生出站流量；当前已超额，不在未确认流量预算前批量下载所有文件。

## 恢复验收

只在隔离本地环境或明确批准的测试项目恢复，绝不把测试恢复指向正式项目。

- 对照表／文件数量和 SHA-256；文件数量一致不能替代内容校验。
- 验证用户账号、业务资料、文章、图片、任务归档和表现快照。
- 验证匿名读取受限、普通会员不能编辑或删除别人发布的任务、后台写操作受限。
- 关闭测试环境的定时任务、webhook、邮件和推送，防止给真实会员重复发消息。
- 记录恢复耗时、失败步骤和备份日期。只有实际恢复通过才能称“可恢复备份”。
