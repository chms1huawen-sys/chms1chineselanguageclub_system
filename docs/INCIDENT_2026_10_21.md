# Public Runtime And Privacy Incident Review

Date: 2026-10-21 (Asia/Kuala_Lumpur).

## Confirmed Causes

1. The public Cloudflare HTML referenced `/assets/index-DgsiDz39.js`, which returned HTML/404 on Cloudflare but JavaScript/200 on Vercel. Existing static article HTML remained visible, concealing the failed React application. The mobile stylesheet hides the expanded navigation until its JavaScript menu operates; the static render did not supply that menu button or the full member action area.
2. The Worker already had a missing-asset redirect, but `/assets/*` was absent from `assets.run_worker_first`. Cloudflare's static asset router returned 404 before the Worker could execute that fallback. A cross-origin module redirect would also require appropriate browser CORS handling; same-origin delivery avoids that dependency.
3. `BlogAnalyticsConsent` treated every page carrying `public-static-preview` as a test page. The formal domain carries this marker too, to keep PWA/member launches on Vercel. Consequently the privacy controls were suppressed independently of the missing runtime.
4. The live Supabase `blog-visit` preflight rejected `https://chms1clc.org` with 403. Restoring the privacy button alone would not restore the statistics connection.

## Repairs

- `/assets/*` now invokes the Worker. Local assets are preferred; missing public JS/CSS files are fetched from the fixed Vercel origin and returned on the public origin. Visitor cookies/authorization and upstream cookies are not forwarded. Redirects, HTML substituted for scripts, and upstream errors fail closed. Module loading does not depend on the R2 snapshot being available.
- Formal-domain privacy controls are distinct from test-preview exclusion. Statistics still require explicit consent and respect browser privacy signals. The existing member/PWA host boundary is unchanged.
- Only the statistics function accepts the formal origin; push/member authorization was not expanded. Untrusted-origin preflight still returns 403.
- Public snapshots record a frontend runtime fingerprint and rebuild when it changes.
- The CMS now returns 405 for unsupported methods rather than disguising them as 503. Unauthenticated POSTs still return 401.
- Health checks distinguish public-to-private 302 redirects from actual Vercel login pages and recursively check entry/lazy JS and CSS, instead of accepting HTML 200 alone.
- `AGENTS.md` records explicit pre-execution approval and mandatory checks of BOTH production environments.

Clarification: snapshot writes already rerender HTML, even when article data does not change. The hourly full-data rebuild interval alone does not prove an hour-long HTML delay. Deployment/synchronization timing and missing assets were the observed problem; the runtime fingerprint is additional release protection.
