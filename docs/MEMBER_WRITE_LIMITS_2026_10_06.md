# 会员写入限制

## 已部署

`supabase_migration_2026_10_06_member_write_limits.sql` 已在正式 Supabase 执行。只读检查确认 9 个触发器启用；不修改旧业务函数定义、任务所有权、审批权限或旧记录。

| 模块 | 每账号每分钟 | 每账号每小时 | 计数位置 |
| --- | --- | --- | --- |
| 任务 | 60 单位 | 600 单位 | tasks 新增／更新／删除；重复计划新增／更新 |
| 财务 | 60 单位 | 600 单位 | 新的 finance_operations 操作记录；报表格式保存 |
| 物品 | 60 单位 | 600 单位 | 新的 inventory_operations 操作记录 |

按固定分钟／小时窗口计算，不是滚动窗口。额度由数据库事务锁和每账号每模块的计数行控制，不使用 IP；同校 Wi-Fi 的账号互不占用。

任务批量写入每个受影响记录算一个单位；立即发布的重复计划同时保存计划和第一期任务，因此通常占两个单位。财务／物品一个业务 RPC 无论内部修改多少业务行，都只算一个新操作记录；原有 operation_id 幂等重试不产生新操作记录，不再扣额度。

查看列表、读取报告、浏览文章不扣额度。没有终端会员身份的服务器／cron 写入不扣额度；通知表不受此次规则影响。服务端的既有身份／权限保护保持不变，不能用客户端提供的 actor_id 代替 auth.uid()。

## 超限行为

- 数据库报错 `PT429 / MEMBER_WRITE_RATE_LIMIT`，携带剩余等待秒数。PostgREST 以自定义 HTTP 状态返回 429。
- 本次事务整体回滚，之前成功记录不变；表单不因这次失败而自动关闭。
- 任务、筹委快捷发任务、财务和物品页面使用同一中英文错误说明，显示等待时间及本次未保存的事实。
- 只增加错误说明，不重设计按钮、布局或圆角。

## 验证与边界

- 隔离数据库测试：分钟上限、小时上限、另一个账号、另一个模块、超限回滚、批量写入、时间窗口重置、服务器作业、幂等重试、浏览器不能读取或修改额度表／直接调用内部函数。
- 装入实际财务、库存和任务生命周期测试，既有付款审批、库存守恒、归还、排程、归档仍通过。新增测试与业务回归共 5 项；原有基本安全 27 项通过。
- 正式库只检查配置与权限元数据，没有为了测试限流发布真实任务、记账、借用或删会员数据。
- 这是成功写入额度，不是所有请求的网关限流。失败事务的计数会随事务回滚；不能声称已拦截所有无效请求洪泛或保证账单不超额。
- 不覆盖任务留言、会员其他资料、其他模块、公开文件读取；上传与推送仍使用其已有独立限制。本轮没有删除资料、付费升级或改凭证。

复测：`npm run security:member-write-test`。
