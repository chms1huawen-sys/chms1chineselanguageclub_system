## 仍然存在，不能隐藏的事项

### 运行风险：Supabase 额度

最后刷新面板显示本期 Sep24-Oct24：Egress **8.145/5GB**；Cached Egress
**0.278/5GB**；Storage平均 **0.222/1GB**；数据库摘要 **0.088/0.5GB**。
仍显示如果持续超额，可能从 **2026-10-30** 起限制请求并返回402。
计量可能延迟；不能保证10月24日换周期自动消除警告。

今天的全量备份会下载数据库/Storage，增加出站量。与早前7.778GB的差额不能
全算成访客流量，也不能仅凭差额精确归因。不要反复全量下载或再跑大流量压测。
Cloudflare/R2降低公开读取压力，不会抹除历史额度，也没有搬走 Supabase 的会员、
认证、编辑、原图上传和定时发布源检查。若 Supabase 被限制，保有已验证公开副本
不等于会员登录、发布和后台操作仍可用。本轮没有擅自升级或改计费。

### 恢复风险：配置补充不是完整灾难恢复

- 今天的数据库/Storage包与两份配置补充包均已核对归档验证记录和 SHA-256，
  各自明文暂存目录已清理，旧备份未覆盖。
- 第二份配置包已含原始 R2 凭据并通过 HeadBucket 只读检查；没有测试写入/删除，
  没有逐值比对其与不可显示的 Vercel Secret，也没有证明本地 Firebase JSON 与
  当前线上 Firebase Secret 完全相同。
- `INVENTORY_CRON_SECRET` 等自定义密钥原值及 Vault 恢复材料仍未补齐。它用于
  任务排程、推送重试和库存等定时入口，不能当成无用配置删掉；原值目前留在线上
  不代表完整重建时能从“名称清单”还原。没有为了备份擅自重设它。
- 完整隔离恢复演练未完成；独立云端副本由用户暂缓，单块硬盘损坏风险仍存在。
- 自动备份排程和实际用量告警尚未建立。文档中的频率/阈值不是已运行的自动服务。
